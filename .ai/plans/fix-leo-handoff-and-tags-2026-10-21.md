# 修复 Leo 节点号交接与 InfluxDB 标签校验

## 目标与非目标

- 按用户确认的最小方案修复复核报告中的 R1/R2，并补充回归、运行全量验证。
- uniqid 每次成功认领节点号后等待至少一个完整毫秒，等待可取消，发布有效租约前重新检查关闭状态、上下文和租约期限。
- InfluxDB 公共响应校验检查 tags 的对象形状与字符串值；保留 tags 缺失、null、空对象及正常标签的语义。
- 不改变公开 API、ID 位布局、配置、持久化或依赖；不实现跨机器时钟偏差/回拨防护，不提交、发布或更新下游；保留其他既有改动。

## 当前理解

- `components/uniqid/component.go` 已有租约门控及同实例同节点号计数器保留，但新实例立即发号可与上一任处于同一毫秒。
- Snowflake 当前版本 v0.3.0 的发号时间单位是毫秒；跨实例时钟准确仍是现有前提。等待只增加节点申请/恢复的启动耗时，不给每次 Generate 增加等待。
- `validateQueryResponse` 未校验 tags，gjson.Map 会将错误类型变为空映射；Query 与 QueryRecords 必须在映射前一致拒绝非法标签。
- 最低 Go1.25 已包含 testing/synctest，可用标准库虚拟时间精确验证毫秒门控与取消，无需增加生产时钟注入或第三方依赖。

## 实施计划

1. 保存当前差异清单与目标文件快照，先创建正式回归并确认修改前失败。
2. 在节点认领成功后增加可取消的一毫秒等待；保留已有节点计数器，等待后检查取消/关闭/租约期限，再发布状态。
3. 校验 tags 非空时必须为对象，标签值必须是字符串；更新对应响应测试。
4. 更新 uniqid 接口说明中的等待和时钟边界；核对实际修改仅限上述模块、测试、说明和本计划。
5. 先运行针对性测试，再执行全量 test/race/build/vet 和格式/差异检查，记录实际结果。

## 验证计划

- uniqid：确定性顺序交接不重复，等待期禁止发号、成功后可发号、等待可取消、等待后租约过期禁止发布；保留已有有效期/续租/关闭测试。
- InfluxDB：tags 缺失/null/空对象/正常字符串对象通过；数组、标量、非字符串值报错，两种查询入口结果一致；保留大整数精度回归。
- `go test -count=1 -timeout=90s ./...`、`go test -race -count=1 -timeout=90s ./...`、`go build ./...`、`go vet ./...`。
- 使用已有 Go 和 vendor；缓存位于 presence-monitor/.cache，不安装宿主依赖。gofmt、git diff --check、既有文件哈希核对。
- 真实服务用例需明确记录是否执行；如未提供隔离端点，准确报告跳过，不将其算作集成通过。

## 风险与影响

- 每次节点认领至少增加 1ms；非常短的 InitTimeout 可能因此明确失败，等待不能掩盖关闭或租约过期。
- 本方案解决已复现的同毫秒交接；仍不保证跨机器时钟偏差/回拨情况下的唯一性。用户已接受该最小方案，不新增持久化协调。
- 新增标签验证会让以前静默接受的畸形响应返回错误，这是本次要求的行为。

## 执行调整

- 初始：仅处理两项已确认遗漏；不重新展开全项目审计。

- 修改前红测已完成：4 个 uniqid 交接/门控/取消/过期测试均失败，标签类型的 10 个非法场景暴露伪成功；正常标签场景保持通过。
- 实现采用认领后的局部 time.Timer，等待后在原状态锁内检查上下文、关闭和期限；没有新增生产时钟抽象或接口。tags 验证复用现有公共校验入口。
- 针对性 race 已通过；补充同一实例重新认领时的门控回归，并扩展现有 etcd 集成用例，覆盖释放节点号后的 20 次新实例接管。Docker 可用，将尝试准备仅本机开放的隔离服务，使全量测试包含可用的真实服务用例；不访问已有业务容器。

## 最终结果与验证记录

- 修改 2 个生产文件：uniqid 在每次成功认领后等待至少 1ms，等待可取消，并在发布前重查上下文/关闭/期限；InfluxDB 在公共响应校验中检查 tags 及其字符串值。
- 新增 handoff_test.go，覆盖 100 次确定性跨实例交接、完整毫秒门控、等待取消、等待后过期及同实例重新认领。query_test.go 增加 15 个标签场景，并检查错误响应不会修改目标结果。
- 扩展现有真实 etcd 集成测试，验证释放节点号后的 20 次新实例接管；更新 uniqid README 说明启动等待与时钟边界。
- 未更改公开 API、ID 位布局、配置、依赖或持久化。除了本计划、新增测试，以及指定模块/说明的 5 个已有文件，其余原有改动的内容哈希均保持一致；原有 67 项 .opencode 删除保持不变。
