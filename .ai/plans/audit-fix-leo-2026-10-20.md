# Leo 全范围审查与确认问题修复

## 目标与非目标

- 用户指定在本仓库修复迁移读取错误，并检查、修复其他确认问题。
- 范围：engine、components、pkg、对应测试、demo 调用与文档、构建/配置；按公开契约和实际调用链检查正常、错误、并发、取消、重连及资源释放。
- 不新增无关功能或无依据的防御层；依赖版本只调整已确认构建冲突的 golog，vendor 由 Go 命令生成；不自动提交/推送，不触碰既有 .opencode 删除。
- presence-monitor 中的 vendor/本地迁移器替代方案不实施；已撤回准备中的测试改动。依赖发布与下游升级不在本次源代码修复中自动执行。

## 当前理解

- 基线 d602fea。工作区已有 .opencode 文件删除，开始状态已记录以便最终逐项核对。
- AGENTS 要求中文注释/文档及既有 Builder 模式。用户要求计划位于 .ai/plans，优先于仓库工作流中的可选目录约定。
- 模块最低 Go1.25，现有宿主 Go1.27.2，仓库包含 vendor。历史审查含已修复项和缺乏根据的推断，只作线索，必须按当前代码反证。
- 已确认迁移问题：unknownMigrationsHaveHappened 遍历结束没有检查 rows.Err；需要在源头修复并补充正常、查询/行读取失败及未知版本回归。

## 实施计划

1. 运行现有构建，建立自有文件/组件覆盖清单、问题、反证、决策与轮次账本。
2. 逐模块检查契约、结构、资源所有权、错误传播、并发关闭/重连和安全边界；追踪 demo 及其他调用方。

5. 再做完整复核，记录新问题、驳回、修复、回归和阻塞；输出中文 QA 报告并核对原有改动未被覆盖。

## 验证计划

- 使用现有 Go1.27.2、GOFLAGS=-mod=vendor、GOTOOLCHAIN=local、GOPROXY=off，缓存和日志写入当前任务的项目缓存目录，不安装宿主组件。
- 修改前 `go build ./...`；修改后针对性红/绿测试、`go test ./...`、`go test -race -count=1 ./...`、`go build ./...`、`go vet ./...`。
- 必要的外部服务测试只使用隔离容器或确定的测试夹具；不访问真实业务账号或服务。
- gofmt、git diff --check、文档链接，以及与开始状态比较保留所有 .opencode 删除。

## 风险与影响

- 框架组件有多个调用方，修改公共接口或生命周期语义前必须核对引用；优先保持接口与既有行为，仅纠正已确认故障。
- 新增测试需要真实覆盖错误/边界，不能放宽预期迁就实现。
- 修复 leo 本地源代码不会自动更新 presence-monitor 锁定版本；最终分别报告源头修复和下游接入状态。

## 执行调整

- 初始阶段：全范围审查、按证据修复。现有删除只保留，不作仓库清理或提交。

- 基线 `go build ./...` 失败：Iris v12.2.11 的 pio.RichOption 调用不兼容 golog v0.1.15 的 printer.RichOption。已核对 Iris 官方 go.mod 及 golog v0.1.12 源码；必须把 golog 调整到兼容的 v0.1.12 并正式重新生成 vendor 才能恢复全量构建。替代方案是升级整套 Iris 或手工改依赖，范围/维护成本更大，不采用。此为已确认构建缺陷的必要依赖调整，覆盖原“不变依赖”的初始假设；其他版本保持，缓存写入 presence-monitor/.cache，宿主全局环境不变。
- 基线针对性 race 测试暴露已有测试夹具的 pingErr 并发读写；会区分夹具竞态和产品状态竞态分别验证，不删除或削弱测试。

- 第一批回归已复现迁移行读取、文件读取/目录标记、符号链接越界、时间轮键冲突与回调死锁。localfile 使用当前最低 Go1.25 已支持的 os.Root 约束实际 I/O，无新增依赖；越界符号链接不再允许，内部相对链接保持可用。时间轮增加待派发队列，使派发与请求接收共同参与 select。
- 修复 golog 后构建继续发现 Iris Builder 把 Runner 当作 Configurator 传入。改为一个自定义 Runner，将已有监听器交给携带超时配置的 app.NewHost(s).Serve(lis)，保持端口预绑定行为。

- 重连回归已复现旧连接未关闭、健康重连后 wrapper 仍使用旧对象、Raw/Do/seq 数据竞争及健康检查忽略关闭取消。将连接操作统一留在既有主循环，锁内发布代次与快照；刷新只取消当前代次。补充重复 Start 防护并落实既有 CloseTimeout，更新生命周期文档。

- 组件 Builder 失败时释放尚未交给引擎的资源，并保留主错误和关闭错误；DB 构造中途失败也释放已创建连接。gRPC 使用原配置 ShutdownTimeout，超时强制停止并返回 DeadlineExceeded。Resty SetTimeout 采用其余 SetX 相同的原地修改语义，保留全部请求配置（调用方若依赖旧方法返回独立实例，须显式独立创建客户端）。InfluxDB 查询解析验证 JSON、协议错误和行列一致性，保持大整数原始精度。

- RabbitMQ 改为每个 channel 独立去重缓存；缓冲区满时等待消费，不确认未处理消息。启动失败取消并回收后台任务；底层拨号和 AMQP/TLS 握手可被组件关闭取消，关闭超时准确返回错误。生命周期用同一锁保护启动登记和关闭，ClearMsgs 使用非阻塞接收。

- Unix 文件描述符回归确认 Log.Close 留下日志文件句柄。管理器记录并关闭自有 writer，不关闭 stdout；Builder 失败同样释放。独立 NewLog 保留既有 API，管理器生命周期之外的独立 logger 不自动拥有 Close 接口。Engine.Wait 返回时注销信号通知。
- uniqid 租约释放后继续发号已复现，Generate 失败语义涉及公开 API；已请求用户在返回 error 与保留签名 panic 之间选择。其他状态同步、快照、watch revision 和取消修复继续进行。

- uniqid 状态发布移入租约观察循环并用同一互斥锁保护；快照复制 map；Start/Close 同步登记并等待两个 worker；事件发送和清理均受取消/超时控制。Watch 从 Get 修订号 +1 开始并处理关闭/错误。租约本地期限按 Grant/KeepAliveOnce 请求开始时间计算，避免缓冲的 KeepAlive 响应延长过期租约；同号重获租约保留雪花序列。公开 Generate 的门控及签名待用户选择后完成。

- 复核发现 InfluxDB SDK 不释放传入的 HTTP 客户端，三种成功/失败关闭路径均经本地连接状态测试确认泄漏；组件明确拥有并关闭 HTTP 传输池。删除重复 Flush，Close 使用 once。存储回归发现 os.Root 无法删除根目录本身，已对可信配置根路径保留原有删除行为，子路径继续受根句柄约束。

- 使用宿主已有 MySQL 5.7.44 镜像创建仅绑定回环地址的临时容器，验证主库成功后从库配置失败会释放主库连接池。测试通过 LEO_TEST_MYSQL_DSN 注入临时连接，计划和报告不保存其值；完成后移除容器与临时凭据文件。以原始源码副本进行反事实红测，再对当前源码做绿测。

- 用户明确选择保留 Generate() ID，租约失效时 panic。已落实生成前/后期限校验、关闭/未启动门控并隐藏底层 Node，补充有效期、正常续租、续租失败、节点号丢失及关闭失败回归。原 Get 错误文档 Skip 测试由实际接口夹具回归替代，没有放宽原预期。

- 第二次全范围复核发现 NATS 错误日志打印完整连接对象，其中包含配置凭据；合成测试值已复现。改为只记录错误，不输出连接/订阅对象，也避免并发格式化 SDK 内部可变状态。

- 发号故障夹具及全量本机测试通过后，再用与客户端对应的官方 etcd v3.6.7 临时容器验证两个实例的节点排他申请、跨原始 TTL 的续租发号与释放。容器仅开放本机测试端口，测试结束清理，不安装宿主服务；测试入口 LEO_TEST_ETCD_ENDPOINT 仅用于显式集成验证。

- Iris 恢复编译后的生命周期复核检查 Build 失败及 Host 配置阻塞：原启动等待到期直接报告成功，且 Build 失败会遗留预绑定端口。新增实际 TCP 端口和 HTTP 超时配置回归；启动必须在 Host 注册后才成功，超时明确报错并关闭本次创建的 server/listener。
